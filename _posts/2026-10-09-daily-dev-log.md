## Today's Update

The volume today was unusually high, and the work split cleanly enough that I can describe it in distinct threads rather than one undifferentiated mass.

The browser-experience-closeout set consumed the bulk of the day — 35 units by the end of it — but that number obscures what was actually happening. The through-line was contract integrity across every surface that a future tenant will touch through the browser: read journeys, projection allowlists, session hydration, and locale composition. The session hydration work (`bec-host-session-hydration`) is worth describing concretely because it's not just wiring: the host now hydrates from the authoritative native principal/account context, refuses stale sessions explicitly, and handles cancellation and retry rather than failing silently or carrying forward a degraded state. That matters because downstream read journeys make authorization decisions against the resolved session, and a stale session that looks valid is worse than one that refuses. Locale composition landed alongside it — the shared locale provider is now composed in the production host and the dashboard plus locale-dependent consumers are qualified against it, which closes a gap where UI text contracts were implicitly trusting whatever locale happened to resolve.

The spend receipt and cohort projection work was about drawing explicit allowlist boundaries before those projections are exercised. The Spend receipt field contract (`bec-spend-receipt-field-contract`) defines which fields are safe for owner exposure, and the enforcement (`bec-spend-receipt-projection-repair`) pushes that allowlist into both the shared REST and MCP projection paths — two separate surfaces that had been inconsistently scoped. The tests prove redaction and refusal without touching the underlying durable evidence, which is the important invariant: the source record doesn't change, only the projection does. The cohort projections followed the same pattern: a bounded allowlist for evidence fields, retention queries fenced by confirmed native identity, and the existing retention metrics service response contract decoded and tested against both valid and malformed transport responses. Decoding that existing contract was necessary before I could fence the query scope; I needed to know exactly what the service was returning before asserting what the browser layer should see.

The Regulatory Knowledge and Cognitive Governance read journeys both reached a complete state today — inventory views, detail views, routes mounted, navigation linked, scope tests, route composition tests, and accessibility validation for Regulatory. Accessibility validation on read journeys at this stage is deliberate: retrofitting landmark semantics after the component tree is deep is substantially more expensive than getting them right at composition time, as the Agent Eval accessibility repair from yesterday demonstrated. The three closed browser verifications (`bec-verify-closed-*`) — agent-tracing, a2ui-approval, and agent-interface — involved observing the source-closed local browser journeys end-to-end, which is the closest analog to integration testing I have before real tenant sessions exist.

The external-agent-surface-preconditions work is where the more structurally consequential decisions landed. ADR-0394 adoption established the external agent surface boundary formally. The OAuth decisions (`esp-oauth-decisions`) resolved custody, authorization server, and grant mapping for issue #5499 — those three questions had been open long enough that adjacent work was starting to make implicit assumptions about them, which I needed to stop. The claims namespace separation (`esp-claims-namespace`) puts claimed and verified agent attributes in distinct envelope sections, which is a security-relevant distinction: a claimed attribute and a verified one should never be in a position where code conflates them by structural proximity. The `AdapterRouterService` generalization (`esp-adapter-router`) extended routing beyond the UCP-specific path, and capability-intent redemption (`esp-intent-redemption`) is now bound to both tenant and principal rather than floating above that context. The forged-claim and rate-limit-evasion tests (`esp-claims-tests`) close the loop on the claims namespace work — I wanted adversarial coverage of the envelope boundary before anything builds on top of it.

The remaining feature sets — trust, workspace, decisions, agent-interface, agent-registry, privacy, and several others — represent a wide surface of smaller but load-bearing changes. The trust timestamp precision work is the one I'll call out specifically: a regression in issuance timestamp precision was exposed (`trust-expose-issuance-timestamp-precision-regression`), SQLite issuance was restored with protected precise storage facts, and the protection definitions and rollback paths were validated. Timestamp precision in issuance records is the kind of thing that looks irrelevant until you're trying to establish ordering guarantees across distributed delegation chains — at that point, microsecond truncation becomes a correctness problem rather than a cosmetic one. The workspace changes enforced evidence display posture across reads, validated graph transport before rendering, and added actor revalidation before projections — all concerned with the same class of problem: the authorization state at render time might not match the authorization state at fetch time, and the workspace needs to be explicit about which one it trusts.

The four agent-auth-audit-remediation items (`aa-decision-reconcile`, `aa-decision-revocation`, `aa-audit-envelope`, `aa-test-audit-envelope`) progressed but ended the day blocked. The execution audit envelope work is the dependency that's holding the others — the reconciliation and revocation paths both need a complete audit record to reason about, and the envelope isn't done yet. That's the first thing to resolve before those threads can close.
