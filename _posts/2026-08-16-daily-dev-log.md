## Today's Update

Three large slabs of work closed today, and they share almost no surface area with each other, which made for an odd kind of day — less a coherent sprint than three separate campaigns running in parallel that each happened to finish.

The most architecturally significant closure was the architecture review remediation, which I've been chipping away at across multiple sessions. Fifty discrete units landed today covering COPPA age classification, idempotency, settlement orchestration, the Experience lifecycle, consent ledger design, subscription cancellation, Contact merge/deletion, and Registry activation compatibility. The through-line across all of it was the same: replace ad hoc string comparisons and scattered state checks with governed enums, typed models, and enforced invariants. The consent ledger work was the most involved — it required introducing an immutable Consent Record schema, a separate Current Consent Posture table, digest-bound append semantics, idempotent expiry recording, and asynchronous compliance evidence attachment, then migrating every existing caller to the new owner interface before removing the legacy writers. The ordering was non-negotiable: you can't delete the old paths until the new paths are proven correct, which is why the red tests came first in each slice. The COPPA classification change is worth calling out specifically — rather than persisting a derived compatibility flag, I made COPPA compatibility state a pure function of Age Status. That's a simpler invariant to enforce and easier to reason about when the classification rules change, which they will.

The Shopify OAuth onboarding for existing stores is complete as a unit. Ten work items covering the architecture boundary, OAuth provider implementation, tenant-bound start and callback actions, idempotent store persistence, first-sync with durable retry, and the replacement of the old secret-entry UI with a one-field connect flow. The security test coverage is explicit about what it's protecting: OAuth rejection paths and tenant isolation, meaning a callback from store A cannot be replayed into store B's tenant context. That boundary is enforced in the provider implementation rather than relying on downstream checks, which is the right layer — by the time a callback reaches application logic, the tenant binding should already be settled. The retry semantics on first-sync are worth noting: I used durable retry rather than fire-and-forget because the first sync failing silently is a worse outcome than a visible pending state. Future operators connecting stores for the first time will see a recoverable state rather than a silent gap.

The PHPStan ratchet remediation closed out 21 items covering a spread of type-level issues: narrowing the authenticated privacy principal keys, tightening tenant-scope audit deduplication values, removing instance access from the static tenant route closure, aligning tenant-scope helpers on Builder static types using late-static generics, and fixing docblock element types on admission evidence references. The `BelongsToAccount` builder contract required a spike before implementation — I needed to prove the late-static binding would actually resolve correctly through the generic before committing to the approach. It did, but the proof step was necessary. The final reconcile regenerated PHPStan evidence and updated the ratchet ledger, so the baseline is now accurate rather than aspirational.

Alongside those three primary threads, I addressed a cluster of smaller but real correctness items: MariaDB check constraint support in migrations (a portability gap that would have surfaced as a runtime error), serializing contact deletion with merges to prevent a race condition where a merge and a deletion could conflict, preflighting contact merge constraints before committing, forwarding the Shopify API version header in ETL requests, and normalizing cancellation replay time in billing. None of these are glamorous, but the merge/deletion serialization in particular is the kind of fix that's much easier to get right before there's data in the system than after. The forward-looking pressure on all of this is the Shopify OAuth path — now that onboarding exists as a complete flow, the ETL and CDP layers it feeds into need to be correct at their own boundaries, and today's CDP fixes directly support that.
