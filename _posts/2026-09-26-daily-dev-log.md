The ordering was intentional: writing the validator before the reconciliation was done would have meant testing against a moving target. The weekly refresh integration is the piece with the most ongoing surface area, since it runs on a schedule and its outputs have to stay consistent with the ledger validator's expectations. The regression tests are scoped specifically to that boundary. Separately, the weekly OI review artifacts for September 20–26 are recorded and the recommendation tracking is updated, which closes the loop on the review cycle that started earlier in the week.

The admin layout cleanup is worth a brief note because it solved a structural problem that would have compounded. Nested `<main>` landmarks were showing up in mounted admin pages, shared admin components, and Blade-hosted React pages — three separate surfaces that all needed the same fix applied differently. Beyond the accessibility correctness, the problem was that rendering dashboards against inconsistent layout roots means any layout-dependent behavior (scroll anchoring, focus management, landmark navigation) is unreliable by construction. Moving the views onto the production admin layout resolves that and gives future admin pages a single target rather than three divergent patterns to choose from. The GPC visitor facts table addition for performance monitoring tests is related in spirit — establishing the right fixture structure before any performance assertions run against it.

The deployment pipeline got a meaningful tightening through three sequential items: emitting a source-bound staging receipt, binding that receipt to a signed admission, then requiring trusted receipt provenance before anything can proceed. These three build on each other in a strict dependency order and the only question I'm still sitting with is where the provenance verification boundary should live when the staging and production admission paths diverge. For now the check is early in the pipeline, which is conservative and correct, but it may need to move if the admission surface expands. The agent instruction drift detection work — inventorying canonical instruction references, correcting the CLAUDE context contradiction, adding the bounded adapter drift check, and verifying it with negative tests — is a different kind of correctness guarantee. The drift check is now testable as a CI gate rather than a manual review concern, which is the right place for it.
