## Today's Update

September 18 was a convergence day — three separate threads that had been running in parallel for weeks all needed to reach a stable state at roughly the same time, and the sequencing between them mattered more than any individual unit of work.

The Revyrie September 23 demo readiness track dominated the day in volume. The remediation pass covered real ground: I traced the Checkout preamble failure to a missing `@viteReactRefresh` directive in the customer Blade template, added it, and wrote an assertion that the Blade emits it — so that failure class is detectable rather than latent. The Price Change admission work was more involved. The core decision was whether to build a new authority model or route through existing policy roles, and I landed on the latter: `CommerceSurfaceController::priceChanges` now goes through `PriceChangeProposalPolicy` rather than introducing a parallel permission structure. The route is registered outside `AdminMiddleware` specifically to let pricing-manager roles through without granting them generic admin access — which I then proved in four separate web tests: the fixture pricing-manager can open the surface, an unrelated pricing-manager cannot see or mutate the subject proposal, a viewer in the same tenant cannot open the console, and a pricing-manager cannot enter generic admin routes. That last test matters because it confirms the carve-out is surgical rather than a hole. After the code landed I pinned the freeze SHA, ran Checkout shipping, payment, and surface suites against it, ran the Price Change RBAC and in-tenant separation tests, and attached the quality-gate outputs as immutable evidence against that SHA. The freeze is now a named artifact rather than just a point in git history.

The appointment scheduling productization work reached a different kind of closure — this track has been about making the public appointment journey defensible before it becomes a real path, and today finished the remaining structural pieces. Google Calendar integration now requires live event lookup evidence before applying changes, which eliminates an entire class of phantom mutations. Appointment dispatch results are fenced to the acquired lease generation, so a stale result from a simultaneous retry cannot overwrite a winning reservation. Pending appointment notices survive unrelated lifecycle revisions, which matters because a future tenant rescheduling an appointment for an unrelated reason shouldn't silently drop a queued confirmation email. Comms email routes through governed single-attempt receipts, and verified guests are bound to Comms channel references so the notification layer has a clean identity anchor. The Commerce side closed out with cancellation refund admission and the full execute-and-reconcile cycle. I also retired the unused `CalendarSync` conflict resolution chain — dead code in this domain is particularly risky because it creates ambiguity about which path is authoritative when two paths claim to handle the same event.

Alongside those two, I ran a complete contention proof suite against MySQL for the appointment workflows: reschedule/expiry contention, public hold contention, Commerce-backed confirmation contention, dispatch contention with stale-result fencing, and refund contention. These aren't speculative — they're documented proof that the locking behavior holds under simultaneous retry conditions on the actual storage layer. The checkout track closed parallel work: nullable checkout UI state narrowed so the frontend doesn't have to defend against undefined at every render site, payment attempt conflicts reconciled, and quote repricing authority hardened. The price-changes feature set added three authorization controls — caller-named approver roles are now rejected, the approval step is derived server-side rather than trusted from the caller, and the cancel/submit/update/read paths all go through the governed layer.

The wedge extension audit for Revyrie opened today as a new track: canonical state established, prior P0/P1 findings revalidated against the live runtime, candidate surfaces inventoried, and the extension mechanism and sequencing documented. That last piece is what I'm least certain about — the mechanism documentation is correct for the surfaces I've already enumerated, but the sequencing assumptions will need revisiting once the first extension actually runs through the path. The September 23 freeze is now pinned at `2fe2f458c9`, the demo origin is verified audience-safe, and the pass-3 audit package is archived. The question going into next week is whether the wedge extension surfaces hold up under the runtime conditions the audit hasn't exercised yet.
